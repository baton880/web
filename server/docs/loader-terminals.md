# Регистрация планшетов ВИ-КОРМ

После обычного входа директором или администратором Android-приложение регистрирует терминал. Вместо суточного JWT оно использует отдельный случайный ключ без срока истечения. Пароль на планшете не сохраняется. Повторный вход нужен после отзыва доступа, смены пароля, удаления пользователя или потери соответствующей роли.

В админ панели (`telemetry-admin.html`) вкладка «Планшеты» находится рядом с «Телеметрия» и «Пользователи». Только ADMIN видит все терминалы и может отзывать доступ с подтверждением. Старый `/loader-terminals.html` требует ADMIN и перенаправляет на эту вкладку. Последняя связь обновляется не чаще раза в минуту и не означает наличие свежего веса.

## Контракт и границы доступа

- `POST /api/loader/terminals`: обычный JWT ADMIN или DIRECTOR, тело `{id,key,name,deviceId}`. Ключ `vkt1_<UUID>_<32 случайных байта base64url>` создаёт клиент и сохраняет до запроса. Повтор той же регистрации возвращает тот же терминал; изменённый или отозванный UUID получает 409. Максимум 100 активных терминалов на пользователя.
- `GET /api/loader/terminals`, `POST /api/loader/terminals/:id/revoke`: только обычный вход сайта с ролью ADMIN; DIRECTOR и GUEST получают 403. Ответы содержат метаданные, без ключей и хешей.
- Терминальный ключ в `Authorization: Bearer ...` действует только внутри `/api/loader`: каталог групп, собственные задания для закреплённого устройства и `/weight?deviceId=...`. `/session` позволяет восстановить результат регистрации после потери ответа. Права ADMIN владельца не дают терминалу доступ к заданиям другого оператора.
- Остальные API сайта и управление регистрациями терминальный ключ не принимают. Старый API телеметрии и обычные JWT продолжают работать.
- При каждом запросе проверяются существование пользователя, роль и версия пароля. Отзыв действует на последующие запросы, уже начатый запрос может завершиться. Сам по себе отзыв не удаляет историю заданий.

## Хранение и обновление

### Удалённое обслуживание

Вкладка сохраняет снимок рабочего экрана, обновление приложения с повторным нажатием для подтверждения, версию APK, состояние задания и команды, а также отзыв доступа.

- `GET /api/loader/terminals/:id/remote`, `POST /api/loader/terminals/:id/remote` с `{type:"screenshot"}` или `{type:"update"}`, `GET /api/loader/terminals/:id/screenshot` доступны только ADMIN с обычной сессией сайта. Отозванный терминал недоступен для этих операций.
- Только терминальный ключ принимает `POST /api/loader/remote/poll` и `POST /api/loader/remote/result`. Терминал получает и завершает только собственную команду.
- Одна незавершённая команда на терминал, срок 24 часа. Обновление ждёт завершения задания; снимок показывает приложение ВИ-КОРМ, исключая PIN, а не весь Android.
- `TerminalRemote` сохраняет команды, heartbeat и последний PNG в приватном каталоге `LOADER_REMOTE_DIR` (по умолчанию `private-terminal-remote` относительно рабочего каталога сервера). Эти файлы не входят в PostgreSQL dump: их нужно сохранять и восстанавливать отдельно, не публиковать как статику и не добавлять в Git.

### Регистрации

В production `LoaderTerminal` хранится в PostgreSQL вместе с остальными данными платформы; используется `PostgresLoaderTerminalStore`. SQLite (`LOADER_TASK_DATABASE_PATH`) сохранён для локальных фикстур и тестов. Хранятся SHA-256 случайного ключа и SHA-256 версии bcrypt-пароля пользователя; исходные ключи и пароли не записываются. Актуальный backup/restore описан в `../../docs/server-platform/OPERATIONS.md`.

Android сохраняет ключ через Android Keystore/AES-GCM. Старый сохранённый JWT автоматически используется для первой регистрации; если он уже истёк, потребуется один вход. Промежуточная регистрация сохраняется до отправки, поэтому потеря ответа не создаёт второй терминал. После активации JWT заменяется ключом: отозванный планшет не регистрируется тайно повторно. Область локального журнала остаётся прежней (сервер, Хозяин, пользователь), задания и очередь сохраняются.

Перенос вкладки не требует изменения APK или миграции данных. Изменения сначала проверяются локально пользователем, затем публикуются в Git по его подтверждению. Деплой выполняется отдельным поручением.

## Проверки

Из корня проекта:

```
node server/scripts/loader-terminals-test.mjs
node server/scripts/loader-tasks-test.mjs
node server/scripts/terminal-remote-test.mjs
```

Изолированный HTTP/SQLite-тест покрывает запрет просмотра и отзыва для DIRECTOR/GUEST, доступ ADMIN, сохранение регистрации DIRECTOR, а также идемпотентную регистрацию, повторное открытие БД, год без истечения, независимость от истёкшего JWT, привязку устройства (включая варианты регистра и завершающего слеша URL), ограничение ADMIN-терминала, отзыв, смену пароля, роли и удаление пользователя. Производственные задания не создаются.

Код Android остаётся локальным по указанию владельца. Прямой Wi-Fi вес, разделение сетей и kiosk mode относятся к следующим этапам.
