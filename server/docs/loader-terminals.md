# Регистрация планшетов ВИ-КОРМ

После обычного входа директором или администратором Android-приложение регистрирует терминал. Вместо суточного JWT оно использует отдельный случайный ключ без срока истечения. Пароль на планшете не сохраняется. Повторный вход нужен после отзыва доступа, смены пароля, удаления пользователя или потери соответствующей роли.

На главной сайта ссылка «Планшеты» открывает `loader-terminals.html`: название, закреплённый Хозяин, время регистрации и последнего обращения, отзыв с подтверждением. Директор видит свои терминалы, администратор — все. Последняя связь обновляется не чаще раза в минуту и не означает наличие свежего веса.

## Контракт и границы доступа

- `POST /api/loader/terminals`: обычный JWT, тело `{id,key,name,deviceId}`. Ключ `vkt1_<UUID>_<32 случайных байта base64url>` создаёт клиент и сохраняет до запроса. Повтор той же регистрации возвращает тот же терминал; изменённый или отозванный UUID получает 409. Максимум 100 активных терминалов на пользователя.
- `GET /api/loader/terminals`, `POST /api/loader/terminals/:id/revoke`: только обычный вход сайта. Ответы содержат метаданные, без ключей и хешей.
- Терминальный ключ в `Authorization: Bearer ...` действует только внутри `/api/loader`: каталог групп, собственные задания для закреплённого устройства и `/weight?deviceId=...`. `/session` позволяет восстановить результат регистрации после потери ответа. Права ADMIN владельца не дают терминалу доступ к заданиям другого оператора.
- Остальные API сайта и управление регистрациями терминальный ключ не принимают. Старый API телеметрии и обычные JWT продолжают работать.
- При каждом запросе проверяются существование пользователя, роль и версия пароля. Отзыв действует на последующие запросы, уже начатый запрос может завершиться. Сам по себе отзыв не удаляет историю заданий.

## Хранение и обновление

Таблица `LoaderTerminal` автоматически создаётся в существующем отдельном `server/runtime/loader-tasks.sqlite3` (или `LOADER_TASK_DATABASE_PATH`). Хранятся SHA-256 случайного ключа и SHA-256 версии bcrypt-пароля пользователя; исходные ключи и пароли не записываются. Нужен согласованный SQLite online backup этого журнала; основная Prisma-БД и телеметрия не мигрируются. Новых зависимостей нет.

Android сохраняет ключ через Android Keystore/AES-GCM. Старый сохранённый JWT автоматически используется для первой регистрации; если он уже истёк, потребуется один вход. Промежуточная регистрация сохраняется до отправки, поэтому потеря ответа не создаёт второй терминал. После активации JWT заменяется ключом: отозванный планшет не регистрируется тайно повторно. Область локального журнала остаётся прежней (сервер, Хозяин, пользователь), задания и очередь сохраняются.

Порядок установки: backup журнала и исходников, обновление сервера с сохранением production-правок, проверки, перезапуск, затем обновление APK. Для отката вернуть прежний серверный код и APK; новые строки журнала сохранять. Старый APK не понимает терминальный ключ, поэтому после отката APK понадобится повторный вход.

## Проверки

Из корня проекта:

```
node server/scripts/loader-terminals-test.mjs
node server/scripts/loader-tasks-test.mjs
```

Изолированный HTTP/SQLite-тест покрывает идемпотентную регистрацию, повторное открытие БД, год без истечения, независимость от истёкшего JWT, привязку устройства (включая варианты регистра и завершающего слеша URL), ограничение ADMIN-терминала, отзыв, смену пароля, роли и удаление пользователя. Производственные задания не создаются.

Код Android остаётся локальным по указанию владельца. Прямой Wi-Fi вес, разделение сетей и kiosk mode относятся к следующим этапам.
