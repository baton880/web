# PostgreSQL очереди: выпуск 20 сентября 2026

Развёрнуто в production. Адреса, commit, перенос, нагрузка и backup — в MIGRATION-STATUS.md; порядок эксплуатации — в OPERATIONS.md. Ниже перечислены свойства и реально выполненные проверки.

## Реализовано

- HOST/RTK durable inbox и replay metadata в одной PostgreSQL с прикладными данными; ACK только после COMMIT приёма, дедупликация повторов.
- Leases с UUID владельца/токена, heartbeat и проверкой владения при завершении. Перезапуск не оставляет processing навсегда; временные ошибки повторяются, malformed сохраняется как permanent.
- Атомарные high-water/dirty/fence изменения; конечная граница накопившейся истории перед replay и расширяемая граница после него. Replay ожидает завершения записи и не очищает более новую версию dirty дня.
- HOST raw, вычисляемые изменения, current pointer и checkpoint сохраняются одной транзакцией. Ошибка откатывает и БД, и память. Повтор после commit не дублирует raw и восстанавливает метаданные/current.
- Полное состояние FSM и вспомогательных Map сохраняется в сжатом AppState checkpoint; свежий процесс восстанавливает типы Date/Map. Старый формат checkpoint также читается. Manual stop использует ту же координацию и транзакцию.
- Один расчётный процесс на хозяйство защищён session advisory lock; потеря владения завершает процесс для перезапуска PM2.
- API и расчёт используют отдельные пулы, чтобы запросы планшетов не заняли все соединения worker. Справочники current объединяют параллельные чтения на 250 мс; сами пакеты, веса и состояние замеса этим кешем не кешируются. Расчёт двух позиций одного HOST использует один снимок групп вместо повторных запросов.
- Частичный индекс активной очереди и настройка autovacuum отделяют обработку от накопленной истории. Nginx лимиты учитывают несколько устройств за одним IP.

## Выполненные проверки

- PostgreSQL/SQLite parity очередей, конкурентный приём, повторы, live/history порядок, rollback, replay fences, stale lease.
- HOST/RTK workers: heartbeat, retry, потерянное владение, malformed, исключение одновременной записи с replay.
- Current pointer: повтор и запоздалый пакет не перемещают актуальный указатель назад; принятый ещё не рассчитанный пакет доступен для чтения.
- Свежий процесс восстанавливает checkpoint; искусственная ошибка checkpoint откатывает raw/business/current и память, повтор проходит. Manual stop исключает конкурентный расчёт и откатывает замес при такой ошибке.
- RTK восстанавливает dirty metadata при повторе после raw commit без дублирования raw.
- Занятые до предела API пулы не блокируют отдельные Prisma/pg соединения расчёта; async context возвращается к API после операции.
- Сравнение replay дня 2026-08-24 на PostgreSQL и SQLite: одинаковые бизнес-результаты, raw counts/time bounds неизменны; искусственный сбой после reset откатывается. Проверка выполнена на отдельных БД, production не пересчитывался.
- Пятиминутная нагрузка 20 HOST 1 Гц + 20 планшетов 2 Гц: все 6000 ACK обработаны, latest pointers правильны, ошибок 0, пороги ACK <200 мс/read <500 мс p95 и drain <10 с пройдены. Числа в MIGRATION-STATUS.md. Более ранние прогоны выявляли задержки и послужили основанием для оптимизации; они не объявлялись успешными.

Резерв ресурсов конечен; многопроцессный расчёт, общий каталог хозяйств, маршрутизация входа, автоматическое внешнее хранение backup и HA этим выпуском не реализованы. Raspberry Pi не менялась.
